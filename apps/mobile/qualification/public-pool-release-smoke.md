# Offline Release public pool smoke

This fixture composes the real Expo public snapshot downloader and fixed HTTPS anchor bridge with the shared pool sync and native MiMC executor. It verifies a synthetic 1,025-leaf depth-20 tree under the existing 2 MiB response and 4 MiB run limits. It does not use a wallet, note, witness, relayer or live chain.

The loopback indexer and HTTPS anchor are separate listeners. RPC replies come from a fixed offline transcript independently of the received snapshot. The anchor accepts two sequential passes of eight different-ID requests. Every pass checks chain ID, both block reads, four fixed pool ABI reads and the current known-root read. The fixture requires nine native Merkle batches after the first pass and before the second. It reads the resulting local lease, validates first and last paths against the fixed root and independently computed path digests, and confirms the lease is retired. A completed native report and the strict loopback server audit must agree.

## Hosted execution

Use the iOS Simulator and Android emulator Release paths in `.github/workflows/mobile-native-qualification.yml` in a dedicated build. This mode has separate launch and evidence from the normal custody, HTTP and POST fixtures. It is not yet a default hosted check.

1. Provision a disposable, short-lived test CA and an HTTPS server certificate signed by that CA with an IP SAN of `127.0.0.1`. Never reuse trust from a physical device or workstation. Run `configure-native-qualification.cjs` in the existing isolated checkout with `CI=true`, `PALI_NATIVE_QUALIFICATION=1`, `PALI_NATIVE_PUBLIC_POOL_QUALIFICATION=1`, `PALI_PUBLIC_POOL_FIXTURE_CA` set to the PEM path, `PALI_NATIVE_HTTP_QUALIFICATION=0`, and the exact source revision in `GITHUB_SHA`. Keep the CA path available to prebuild. The Android plugin trusts the exact CA only for the fixture loopback domain. For iOS, install that CA with `simctl keychain add-root-cert` into the dedicated disposable simulator. The native downloader continues to use ordinary server trust on both platforms.
2. Run `node qualification/run-public-pool-fixture.cjs <ios|android> .native-qualification.json <ca.pem> <server.pem> <server.key> <fresh-host-report-path>` with the same CI and public-pool flags. The host prints the owned launch URI, ports and expected report basename. Both listeners bind only to loopback.
3. Install the isolated Release application. Launch the URI using the existing `PaliQualificationURL` argument on iOS. For Android, set up two owned no-rebind adb reverse mappings on the verified CI emulator before opening the URI, then remove exactly those mappings. Reuse the existing command runner and device ownership rules. Copy the reported file from the fixture sandbox to the fresh host report path. The host accepts only a matching build, CA digest, launch token, platform, zero fallback network calls, and complete server audit.
4. Retire the isolated simulator/emulator, local listeners, and test certificates after the run.

The host test exercises actual HTTP and HTTPS sockets, shared verification, the same bridge adapter with a Node substitute for the native module, and changed-leaf/second-pass rejection. It cannot establish Expo bridge execution or platform trust. The retained 13,113,982-byte public snapshot and its separate 16 MiB qualification overlay remain governed by the scale plan. This fixture qualifies neither that payload size nor live provider behavior.
