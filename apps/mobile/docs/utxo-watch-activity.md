# Account-wide public UTXO activity

The active Bitcoin/Syscoin Activity screen reads indexed account history through the existing shared extension Blockbook reader. Address records query their address. Public extended-key/descriptor records query the canonical account using SyscoinJS's existing account route; they do not enumerate addresses or run another scanner. The canonical identifier stays in WatchOnlyAuthority's private record session and is never included in UI snapshots, copied values, returned transaction rows or error text.

Platform composition supplies the trusted activity reader. UI code can ask only for a page on the selected authority context. The authority captures account, network, generation and stored-record identity, validates the record set before and after the read, and owns cancellation independently of its balance operation. Account/network changes, A-B-A transitions, lock, idle expiry, background/focus loss, tab departure and unmount revoke outstanding work. The reader captures scalar inputs before awaiting and uses one request-local transport/session, never a mutable global current-request slot.

Each page verifies the configured backend coin/network/chain and genesis using the existing UTXO session. The actual SyscoinJS fetchBackendAccount call receives the canonical identifier, page options, account/address flag, no signer, and its supported sixth fetch/signal argument. It therefore cannot advance receiving/change indexes. Shared txsummary validation and txslight fallback are the extension's own implementation. Cancellation is checked before fallback. HTTP unavailability can reach that explicit fallback within the same deadline; identity, body-format, byte-limit and cancellation failures stay terminal.

The former address→txids→raw-transaction scanner and per-page block anchor are removed. Pending history is allowed and block data may be null. Existing shared block predicates define observed inclusion; no confirmation-depth, finality or settlement policy is introduced. A successful fresh same-txid observation supersedes retained status. Partial paging does not prove absent rows were deleted, and page churn may prevent a complete historical snapshot.

The page size is20. Transport consumption and JSON work are bounded to1 MiB per request session, with a30-second deadline,20,000 JSON values and depth16. Before shared normalization, the native work boundary rejects more than20 rows or native integer text longer than the existing78-digit public-amount domain; short invalid values still follow the shared interpretation rules. The public list retains at most100 rows across five pages and can navigate to older or newer windows; there is no five-page backend cutoff. Oversized, malformed or wrongly identified responses fail without publishing partial rows. A first failure is unavailable; a later failure preserves the current rows with a stale notice until another explicit refresh/navigation action.

All native interpretation comes from the existing shared amount helpers. Account change is addressValueOut−addressValueIn when both are valid. Whole-transaction fee is separately labelled. Transfer intent requires the shared ownership/conservation evidence; unknown values remain null. SPT quantities already present in an account page use the same shared exact-decimal amount and display helpers as the extension. Direction and account/transaction scope come only from that shared result; compact bridge summaries remain account-scoped. Missing, unsafe or ambiguous token quantities stay unavailable and never fall back to native funding. Optional symbols use the existing bounded display-text guard; asset identifiers retain the full decimal uint64 domain. Memos, scripts, raw extended keys, raw token metadata objects and provider-supplied URLs do not reach the public view. No additional transaction-detail request is made; full bridge/detail hydration remains a separate feature.

Activity loads automatically only for the mounted, foreground, current context. Refresh is explicit; there is no background polling or new notification capability. Details preserve the current list/scroll state. Copy and explorer actions retain the existing per-operation ownership, lifecycle and selected-row guards; only a validated transaction ID is copied or included in the fixed explorer URL.

Tests use actual shared functions, SyscoinJS routing, protected public-record codecs and closed synthetic HTTP. They cover receive/change ownership, large exact native amounts, ambiguous inputs, pending/reorg updates, page6 and bounded windows, fallback/empty/error responses, record changes, cancellation and public-view isolation. Browser rendering and host tests do not establish deployed-provider correctness, device HTTP behavior, physical clipboard/privacy behavior or full wallet parity. Those remain explicit qualification gates.
