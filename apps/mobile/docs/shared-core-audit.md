# Shared-core audit

Source basis is the combined candidate through #1275 at `d27a816f92ac120647ab04aebfc8b28248c66a72` plus the shared fee approvals, ordinary UTXO binding and SLH-DSA state/runtime integration in this branch. Hosted validation of that integration is pending. This records implementation and remaining work. Native qualification is tracked separately in the [parity matrix](../design/PARITY_MATRIX.md).

| Area | Implementation and boundary |
| --- | --- |
| Accounts | Both hosts use the SDK host/session contract, account creation/allocation and shared `source/wallet/accountRecords.ts` transitions. Mobile persists complete SDK maps and restores them on ordinary unlock. It has no separate HD allocator or per-unlock account rederivation. |
| Recovery | Both hosts use `source/wallet/accountRecovery.ts` and `importedAccountRecovery.ts`. Chrome supplies its storage adapter and mobile supplies guarded SQL replacement. Matching-phrase recovery preserves retained imported copies, recognized notes and signed records. A phrase cannot recreate absent independent secrets. Mobile has one first-release data format. |
| UTXO discovery and history | Public validation and derivation use the SDK. Owned Blockbook reads through SyscoinJS perform account receive/change discovery. Both hosts share transaction amounts, participant projection, status freshness and selected-detail caching. Lists and paging do not request every full transaction. The shared enabled defaults support native custody, and mobile custom SDK-recognized UTXO registrations remain watch-only. |
| UTXO send | Mobile HD and WIF native-coin send/MAX use the SDK quote and signer. Both hosts use `utxoSignedRecords.ts` and `utxoSubmission.ts` for authenticated retention before POST and explicit exact-byte replay. Both hosts now use the common `utxoSignedBinding.ts` transaction/fee binding. The extension retains renderer attestation around that shared policy. Specialized external and SPT PSBT behavior remains explicit. Native hardware and SPT send are unfinished. |
| EVM fees and limits | Both hosts consume SDK fee helpers and the shared network protocol registry. Both hosts use `source/shared/evmFeeApproval.ts` for immutable fee approvals, expiry and refreshed-quote validation. The extension background owns its approval handles. Native bounded RPC reads adapt transport without a separate per-chain confirmation or settlement policy. |
| EVM signing and submission | Both hosts use the SDK software signer and shared authenticated signed-record/replay policy. Native verifies returned bytes against the approved envelope. Storage adapters retain exact bytes before POST and preserve known RPC acknowledgements across later bookkeeping failure. Predecessor bytes survive new sends and account removal. |
| Nonces and replacements | Supplied nonces, including zero, remain authoritative. Mobile saved pending type-0/type-2 EVM sends can initiate cancellation or Speed Up for the selected HD/imported payer. Speed Up preserves the exact native or reviewed ERC20 execution. The journal checks the original inside the replacement write, and transport rechecks live eligibility before dispatch. Both hosts can review a same-nonce cancellation for an eligible retained transaction whose nonce is still executable. Broader multiple-pending UX remains open. |
| Assets and history | Both hosts share exact ERC20 metadata, units, encoding and explorer/history normalization. Native manual import, holdings suggestions and saved ERC20 assets are implemented. Collectible suggestions, ownership checks and explicit saved-list changes are implemented. Native collectible Send verifies the exact item and quantity, checks current ownership and retains signed bytes before dispatch. Eligible saved transfers can be retried or cancelled through explicit review. Retained pending submissions use the shared observer, while list reads avoid per-row RPC enrichment. |
| Secret reveal | Mobile EVM key and imported UTXO WIF reveal require backup confirmation and fresh password authentication. WIF reveal verifies the selected address and shows the canonical network/script label. Screens clear on hide, navigation and authority loss. UTXO HD key reveal remains unavailable. |
| Network text | Extension and mobile forms use `source/shared/networkText.ts`. Full stored values and identity survive display ellipsis. Custom endpoint registration uses owned identity checks before saving. |
| Device unlock | Shared enrollment/revocation and protected mobile credential adapters exist. Mobile production composition and extension quick-unlock activation remain unwired. The native adapter requests authenticated, passcode-bound device-only storage, while password fallback and real-device invalidation/lifecycle gates remain required. |
| SLH-DSA | Shared encrypted-state and runtime factories preserve the extension's per-key queues, session binding and usage accounting. The extension supplies its existing offscreen execution adapter. Mutation and signing callers must pass a captured generation. Native execution, setup and signing UI remain open. |

Native adapters own SQLCipher/SecureStore, protected files, HTTP, application lifecycle and native presentation. Shared wallet policy owns derivation, fee and nonce semantics, signed-byte validation, recovery and durable submission. A host-specific transport or screen does not justify a second wallet-policy implementation.

The shared UTXO detail cache retains at most 100 bodies within 8 MiB, with five-minute freshness and two active reads. Mobile summaries have their own 8 MiB bound and up to 120 transient references while merging the 100-row window. Both caches are memory-only. Indexed observations can change after a reorg and do not establish destination-chain bridge settlement.

The extension manifest/Yarn lock and mobile manifest/npm lock pin official Keyring **2.1.5**, Network **2.0.0** and SyscoinJS **1.0.280**. The resolved dependency graph also uses Core **1.0.30** and Utils **1.1.281**. Consumer patches are absent.

At `d27a816f`, Android custody/cold-restart CI passed. iOS Simulator CI passed HTTP, crypto and expected protected-storage refusal. Earlier physical-iPhone evidence at `f1316c50f66004772946e28aa94a9e4d0b3db54b` with SDK 2.1.2 covered offline import/create/restart and a normal-app password/lock flow with backup incomplete. Those historical checks do not qualify the current candidate, completed backup, WIF reveal, cancellation, biometrics or live transfers.
