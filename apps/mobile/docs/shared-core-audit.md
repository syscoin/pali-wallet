# Shared-core audit

This describes the November 10 development candidate with shared EVM approvals, native Ledger signing, Trezor wallet-send integration and the default ECDSA smart-account deployment flow. Native qualification remains revision-bound in the [parity matrix](../design/PARITY_MATRIX.md).

| Area | Implementation and boundary |
| --- | --- |
| Accounts | Both hosts use the SDK host/session contract, account creation/allocation and shared `source/wallet/accountRecords.ts` transitions. Mobile persists complete SDK public maps and restores them with an independent public-view credential on ordinary unlock; spending credentials are read only during explicit private operations. It has no separate HD allocator or per-unlock account rederivation. |
| Recovery | Both hosts use `source/wallet/accountRecovery.ts` and `importedAccountRecovery.ts`. Chrome supplies its storage adapter and mobile supplies guarded SQL replacement. Matching-phrase recovery preserves retained imported copies, recognized notes and signed records. A phrase cannot recreate absent independent secrets. Mobile has one first-release data format. Replacement credential cleanup is recorded before OS staging and retried on cold reopen, including cancellation and uncertain commits. |
| UTXO discovery and history | Public validation and derivation use the SDK. Owned Blockbook reads through SyscoinJS perform account receive/change discovery. Both hosts share transaction amounts, participant projection, status freshness and selected-detail caching. Lists and paging do not request every full transaction. The shared enabled defaults support native custody, and eligible mobile custom SDK-recognized UTXO registrations use the same owned discovery contract. |
| UTXO send | Mobile HD, imported BIP84 and WIF native-coin send/MAX use the SDK quote and signer. Ledger and Trezor use their existing shared PSBT adapters. Both hosts use `utxoSignedRecords.ts` and `utxoSubmission.ts` for authenticated retention before POST and explicit exact-byte replay. Both hosts now use the common `utxoSignedBinding.ts` transaction/fee binding. The extension retains renderer attestation around that shared policy. Specialized external and SPT PSBT behavior remains explicit. Ordinary SYSX allocation sends are implemented. Other SPT operations and physical hardware qualification remain open. |
| EVM fees and limits | Both hosts consume SDK fee helpers and the shared network protocol registry. Both hosts use `source/shared/evmFeeApproval.ts` for immutable fee approvals, expiry and refreshed-quote validation. The extension background owns its approval handles. Native bounded RPC reads adapt transport without a separate per-chain confirmation or settlement policy. |
| EVM signing and submission | Both hosts use the SDK software, Ledger and Trezor signers and shared authenticated signed-record/replay policy. Selected-account and signing-target identities are explicit, and vault state is bound once per keyring instance. Native verifies returned bytes against the approved envelope. Storage adapters retain exact bytes before POST and preserve known RPC acknowledgements across later bookkeeping failure. Predecessor bytes survive new sends and account removal. |
| Nonces and replacements | Supplied nonces, including zero, remain authoritative. Mobile saved pending type-0/type-2 EVM sends can initiate cancellation or Speed Up for the selected HD/imported payer. Speed Up preserves the exact native or reviewed ERC20 execution. The journal checks the original inside the replacement write, and transport rechecks live eligibility before dispatch. Both hosts can review a same-nonce cancellation for an eligible retained transaction whose nonce is still executable. Automatic queueing reconciles local reservations with node state; the selected account/network has a paged Saved pending view and an explicit local activity/nonce reset. |
| Assets and history | Both hosts share exact ERC20 metadata, units, encoding and explorer/history normalization. Native manual import, holdings suggestions and saved ERC20 assets are implemented. Extension and native dapp reviews share exact transfer summaries and metadata validation, including Smart single/batch calls. EVM All networks aggregates only the selected account across saved networks, while concrete filters do not fan out to hidden networks or sibling accounts. Collectible suggestions, ownership checks and explicit saved-list changes are implemented. Native collectible Send verifies the exact item and quantity, checks current ownership and retains signed bytes before dispatch. Eligible saved transfers can be retried or cancelled through explicit review. Retained pending submissions use the shared observer, while list reads avoid per-row RPC enrichment. |
| Native Trezor handoff | The platform adapter only opens official Suite app links and receives bounded public callback data. Normal background locking retires the old SDK invocation. A new unlock and explicit continuation re-enter the existing account or transaction flow; exact request matching precedes reuse of a response. Hardware keys never enter native storage. Real Suite/device qualification remains open. |
| Secret reveal | Mobile EVM key and imported UTXO WIF reveal require backup confirmation and fresh PIN or OS biometric authentication. WIF reveal verifies the selected address and shows the canonical network/script label. Screens clear on hide, navigation and authority loss. HD UTXO key reveal follows the same fresh-authentication and verified public-identity boundary. |
| Network text | Extension and mobile forms use `source/shared/networkText.ts`. Full stored values and identity survive display ellipsis. Custom endpoint registration uses owned identity checks before saving. |
| Device unlock | Shared enrollment/revocation and protected mobile credential adapters exist. Native setup, locked entry and Security settings use that shared enrollment. Extension local PRF passkey unlock is implemented with password fallback. Native PIN verification/public-view storage is separate from spending credentials; optional biometric enrollment wraps only the public-view key. Native signing and reveal still require fresh operation authentication. Real-device invalidation and lifecycle qualification remain required. |
| SLH-DSA | Shared encrypted-state and runtime factories preserve the extension's per-key queues, session binding and usage accounting. The extension supplies its existing offscreen execution adapter. Mutation and signing callers must pass a captured generation. Native execution, setup and signing UI are implemented behind qualified capability checks; native/model-specific execution and performance qualification remain required. |

Native adapters own SQLCipher/SecureStore, protected files, HTTP, application lifecycle and native presentation. Shared wallet policy owns derivation, fee and nonce semantics, signed-byte validation, recovery and durable submission. A host-specific transport or screen does not justify a second wallet-policy implementation.

The shared UTXO detail cache retains at most 100 bodies within 8 MiB, with five-minute freshness and two active reads. Mobile summaries have their own 8 MiB bound and up to 120 transient references while merging the 100-row window. Both caches are memory-only. Indexed observations can change after a reorg and do not establish destination-chain bridge settlement.

Both hosts pin official Keyring **2.1.12**, including the operation-lifetime contract from **Sysweb3 #108**. Mobile explicitly selects operation-scoped secrets; the extension retains its existing unlocked-session policy. Network **2.0.0**, SyscoinJS **2.0.0**, syscointx-js **2.0.0**, Core **1.0.30** and Utils **1.1.282** remain pinned. Hosted and native checks apply to exact current heads; the [historical candidate record](https://github.com/syscoin/pali-wallet/blob/3d7c784d/vendor/sysweb3-operation/REVIEWED-CANDIDATE.json) does not qualify the official-package build.

At `d27a816f`, Android custody/cold-restart CI passed. iOS Simulator CI passed HTTP, crypto and expected protected-storage refusal. Earlier physical-iPhone evidence at `f1316c50f66004772946e28aa94a9e4d0b3db54b` with SDK 2.1.2 covered offline import/create/restart and a normal-app password/lock flow with backup incomplete. Those historical checks do not qualify the current app, completed backup, WIF reveal, cancellation, biometrics or live transfers. [Exact native run](https://github.com/syscoin/pali-wallet/actions/runs/42154521873)

Native dapp sessions, message/transaction approvals, allowance editing, Ledger signing, ECDSA smart-account deployment, native-currency MAX, ERC20 and NFT sends are implemented in source. Smart sends use the shared validator metadata reader, preparation, owner signing, payer policy and submission helpers. Private-pool and Sentry screens/controllers, snapshot tooling and optional activity/guardian notifications are implemented with their explicit capability gates. Remaining on-chain P256 acquisition, mixed Trezor/non-ECDSA continuations, physical devices, funded services and OS background delivery require the specific work or qualification listed in the [parity matrix](../design/PARITY_MATRIX.md); this source audit is not a release qualification.
